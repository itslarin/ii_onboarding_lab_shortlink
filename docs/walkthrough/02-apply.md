# Фаза 2: apply — реализовать задачи

**Цель:** пройти по `tasks.md`, реализовать код, добиться зелёных тестов
лабы.

## Шаг 1. Запустите тесты — увидьте «красное»

```bash
mvn test -Dtest.tags=lab01
```

Тесты **должны падать** — реализации ещё нет. Это ваша отправная точка
и одновременно карта: каждый упавший тест — задача.

## Шаг 2. Запустите apply

```
/opsx:apply lab01-shortlink
```

AI предложит план и начнёт реализацию по `tasks.md`. Вы можете:
- согласиться с планом целиком;
- выполнять задачи по одной;
- остановиться и поправить `tasks.md`, если план расходится с постановкой.

## Шаг 3. Цикл: тест → реализация → тест

Не ждите, пока AI «сделает всё». Работайте итерациями:

1. Выберите упавший тест (например, `C1`).
2. Посмотрите, чего не хватает (контроллер? модель? хранилище?).
3. Реализуйте минимальный кусок.
4. Запустите **только этот тест** или весь набор лабы:

```bash
mvn test -Dtest.tags=lab01
```

5. Повторите для следующего теста.

**Почему так:** тесты — это исполняемая спека. Они говорят, **что**
должно быть, не подсказывая **как**. Если AI предлагает решение, которое
не ведёт к зелёному тесту, — это сигнал уточнить `tasks.md` или
`proposal.md`.

## Шаг 4. Отмечайте задачи

В `tasks.md` меняйте `- [ ]` на `- [x]` по мере выполнения. Это нужно
для фазы `archive` (она предупредит, если задачи не закрыты).

## ✅ Готово, когда

- [ ] `mvn test -Dtest.tags=lab01` — все тесты зелёные
- [ ] `tasks.md` — все задачи отмечены `[x]`
- [ ] В коде нет обходных путей «чтобы тест прошёл» (например,
      захардкоженных ответов)

## ⚠️ Типичные ошибки

| Симптом | Что делать |
|---|---|
| Тест C8 (`415`) не зеленеет | У `@PostMapping` должен быть `consumes = [MediaType.APPLICATION_JSON_VALUE]` |
| Тест C11 (регистр) не зеленеет | Поиск по `shortCode` должен быть регистрозависимым (обычный `Map`/`ConcurrentHashMap` это даёт) |
| C13 не зеленеет | Убедитесь, что нет дедупликации: каждый `POST` создаёт новый код |
| AI предлагает «упростить» тест | Отклоните: тесты — критерий приёмки, их не меняем |
