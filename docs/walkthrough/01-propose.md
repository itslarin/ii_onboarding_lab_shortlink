# Фаза 1: propose — сформулировать изменение

**Цель:** превратить постановку лабы в артефакты OpenSpec: `proposal.md`,
`specs/`, `tasks.md`. Пока **не пишем код**.

## Шаг 1. Прочитайте постановку

Откройте `docs/labs/lab01.md`. Обратите внимание на:
- контракты API (раздел «API-контракты»);
- таблицу тестовых сценариев `C1–C13` — это ваш критерий приёмки;
- раздел «Вне scope лабы 01» — что **не** входит в изменение.

## Шаг 2. Запустите propose

В чате OpenCode:

```
/opsx:propose lab01
```

Команда создаёт `openspec/changes/lab01/` и генерирует
артефакты. Для `spec-driven` схемы это `proposal.md`, `specs/`,
`design.md`, `tasks.md` (набор может отличаться в зависимости от версии;
главное — proposal и tasks).

> Если формулировка изменения пока не ясна, начните с `/opsx:explore` —
> это режим «подумать вслух» без создания артефактов.

## Шаг 3. Заполните `proposal.md`

AI сгенерирует черновик, но его нужно **отредактировать**. Ориентируйтесь
на шаблон:

```markdown
# Change: lab01

## Why
Сервис коротких ссылок отсутствует. Нужен минимальный API для создания
короткой ссылки и редиректа по ней, чтобы пройти полный цикл SDD.

## What Changes
- Добавить `POST /links` — создание короткой ссылки (C1–C8, C13).
- Добавить `GET /{code}` — редирект по коду (C9–C12).
- Хранение — in-memory (`ConcurrentHashMap`).
- Генерация кода — случайная Base62, 6 символов.

## Out of Scope
- Дедупликация (во второй лабе).
- Персистентность, статистика, кастомные коды.

## Rollback Plan
Удалить `LinkController`, `RedirectController`, модель `Link` и
in-memory хранилище. Тесты лабы остаются, но снова становятся красными —
это ожидаемо.
```

**Зачем это:** `proposal.md` — «почему и что», он фиксирует границы
изменения. Если в нём нет `Out of Scope`, AI может «додумать» лишнее.

## Шаг 4. Проверьте `tasks.md`

`tasks.md` — чек-лист задач в формате `- [ ] X.Y Описание`. Убедитесь,
что задачи:
- покрывают все слои (контроллер, сервис, хранилище);
- заканчиваются проверкой тестов лабы (например, `mvn test -Dtest.tags=lab01`);
- не выходят за `Out of Scope`.

Если задачи слишком крупные — попросите AI разбить их
(`/opsx:update` или уточните в чате).

## ✅ Готово, когда

- [ ] `openspec/changes/lab01/` существует
- [ ] `proposal.md` содержит `Why`, `What Changes`, `Out of Scope`, `Rollback Plan`
- [ ] `tasks.md` — чек-лист, покрывающий C1–C13
- [ ] В `specs/` есть сценарии (Given/When/Then) или требования, покрывающие контракты

## ⚠️ Типичные ошибки

| Симптом | Что делать |
|---|---|
| `/opsx:propose` не распознаётся | Проверьте, что OpenSpec инициализирован (`openspec init`) и skills подхвачены (перезапустите IDE) |
| Артефакты создались в `main`, а не в ветке | Проверьте `git branch`; вернитесь в свою ветку и повторите |
| `proposal.md` пустой или слишком общий | Заполните вручную по шаблону; AI-черновик — только основа |
