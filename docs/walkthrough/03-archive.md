# Фаза 3: archive — завершить изменение

**Цель:** «свернуть» изменение: спека переезжает в основную,
изменение — в архив. После этого лаба считается завершённой.

## Шаг 1. Убедитесь, что готовы

- [ ] `mvn test -Dtest.tags=lab01` — зелёный
- [ ] `tasks.md` — все задачи `[x]`
- [ ] `proposal.md` и `specs/` отражают то, что реально сделано

## Шаг 2. Запустите archive

```
/opsx:archive lab01
```

Если задачи не закрыты или delta-спеки не синхронизированы, OpenSpec
**предупредит**, но не заблокирует. Предупреждение — повод остановиться
и проверить.

## Шаг 3. Что происходит «под капотом»

**До архивации:**

```
openspec/
├── changes/
│   └── lab01/
│       ├── proposal.md
│       ├── specs/
│       ├── design.md
│       └── tasks.md
├── specs/          ← пусто (или только то, что было раньше)
└── archive/        ← пусто
```

**После архивации:**

```
openspec/
├── changes/
│   └── archive/
│       └── 2026-11-22-lab01/   ← изменение целиком
│           ├── proposal.md
│           ├── specs/
│           ├── design.md
│           └── tasks.md
├── specs/
│   └── ...          ← delta-спеки влиты в основную спеку
└── ...
```

**Ключевое:** содержимое `specs/` из изменения **сливается** в
`openspec/specs/` по правилам `ADDED` / `MODIFIED` / `REMOVED`.
Изменение целиком сохраняется в `archive/` для истории.

## Шаг 4. Заполните `NOTES.md`

В корне ветки создайте `NOTES.md` (5–10 строк):

```markdown
# NOTES — lab01

- Что сделал: ...
- Где застрял: ...
- Что было неочевидно в OpenCode/OpenSpec: ...
- Что улучшил бы в постановке лабы: ...
```

Это не «сдача», а обратная связь для улучшения онбординга.

## ✅ Готово, когда

- [ ] `openspec/changes/lab01/` больше нет (переехал в `archive/`)
- [ ] В `openspec/specs/` появились требования/сценарии лабы
- [ ] `NOTES.md` заполнен

## ▶️ Дальше
